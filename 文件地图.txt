第 0 节 · 30 秒用法（先看这里）
====================================================================

  1）我有具体需求（例：气泡想圆一点 / AI 老是写旁白）
       → 直接翻【第 2 节 · 对症下药速查表】，左边找症状，右边就是文件

  2）我想确认某个文件是干嘛的、能不能动
       → 翻【第 3 节 · 逐文件说明】，按目录顺序排列，每个文件都有图标分级

  3）我想知道聊天记录 / 记忆 / 布局存在哪、清掉会怎样
       → 翻【第 4 节 · 数据存在哪】

  4）我想加一个新 App / 一个新模块
       → 翻【第 5 节 · 新增东西的标准动作】

  5）改完怎么验证
       → 命令行跑 npm run build，不报错即通过（第 6 节）

  重要：一次只改一件事。改一个 App 就只碰那个 App 的文件，
        别顺手"优化"别的地方，出问题时才好回退。

─── 3.3 stores（数据仓，界面显示什么都从这里读）─────────────────

src/stores/desktop.js                   451 行   🔴 地基
  作用：桌面唯一真相源
  · state/getter：pages（两页布局）、dock、windows（窗口）、settings、wallpaper、
                  unit（缩放）、metrics（每格像素）、openWindows、minimizedWindows、
                  dragging（正在拖谁）、dropPreview（落点高亮）、gridSize
  · action：openApp / closeApp / minimizeApp / restoreApp / focusApp（窗口）
            setSetting / setWallpaper / resetLayout（桌面设置）
            moveIcon / moveWidget / canDrop / renameIcon / removeIcon（布局）
            setWidgetProps（改组件里的字/图，例如小组件标题）
  · defaultLayout()：出厂布局（想改图标初始位置就改它）
  · 存储：localStorage 'vphone.desktop.v1'，LAYOUT_VERSION=3
  风险：改字段名 / 结构会让老用户的桌面布局读不出来。要加字段请像现有代码那样
        在读取时补默认值（不要直接改 key 名）

src/stores/aiConfig.js                  330 行   🟡
  作用：AI 接口配置（多套档案，最多 20 套）
  · state：profiles、activeId、testing、testResult、modelsMap、modelsLoading、modelsError
  · getter：config（当前生效的那套）、isConfigured、canAddProfile、endpoint、
            headerPairs、modelOptions（当前档案拉到的模型列表）
  · action：update / setModel / applyPreset / runTest / loadModels /
            selectProfile / createProfile / renameProfile / removeProfile / reset / resetAll
  · 存储：'vphone.ai.v2'（旧版 'vphone.ai.v1' 会自动迁移成第一套，迁移后删旧 key）
  注意：换地址 / 密钥 / 请求头会清掉已拉取的模型列表（旧列表不可信）

src/stores/worldbook.js                 402 行   🟡
  作用：世界书条目 + 文件夹 + 注入算法（对齐 SillyTavern World Info）
  · state：entries（条目）、folders（文件夹）
  · 条目字段：name / scope（global|local）/ position（before|middle|after）/
              constant（必读）/ keys（关键词数组）/ requireAll / order / depth / enabled / folderId
  · action：add / update / remove / duplicate / toggle、addFolder / renameFolder /
            toggleFolder / removeFolder
  · matches(entry, scanText)：空关键词=不命中；constant=永远命中；
            requireAll=true 要全部关键词都出现，否则任一出现即可
  · collect({ ids, scanText })：返回 { before[], middle[], after[{content,depth}], picked[] }
  · 存储：条目 'vphone.worldbook.v2'（自动迁 v1）、文件夹 'vphone.worldbook.folders.v1'
  注意：删文件夹不删条目（条目回到"未分组"）；文件夹只影响列表分组，不影响注入

src/stores/memory.js                    278 行   🟡
  作用：记忆条目 + 整理进度 + 注入渲染
  · 结构：books = { [chatId]: { chatId, name, items[], coveredCount, lastAt } }
  · 条目字段：text / level（3 关键 ★★★、2 重要 ★★、1 次要 ★）/ kind / when / quote / hits
  · coveredCount = 原始 messages 数组下标（不是过滤后的条数），进度全靠它算
  · action：absorb（整理结果入库，去重合并 + hits 强化，hits≥3 升为关键）/
            addItem / updateItem / cycleLevel（点星星换档）/ removeItem /
            clearBook / resetProgress
  · collect(chatId, {max, minLevel})：按等级取前 N 条

第 5 节 · 新增东西的标准动作（照着做不会漏）
====================================================================

【5.1 新增一个 App】需要动 3~4 个地方，缺一不可
  ① src/views/apps/Xxx.vue          新建页面（可先照 Memo.vue 的 6 行占位）
  ② src/apps/registry.js            在 APPS 里加一条：id / name / icon / accent /
                                    window / phase / desc / load: view('Xxx')
  ③ uno.config.js 的 safelist      把新的 icon 类名加进去（漏了线上就是白块）
  ④ （可选）src/stores/xxx.js      该 App 需要独立数据仓时新建
  ⑤ （可选）DOCK_IDS               需要放 Dock 就往里加 id
  注意：16 个 App 已经全部注册，只是 12 个页面还是占位；
        要实现某个现有 App，只需替换它的 .vue，前 4 步都不用做

【5.2 新增一种桌面小组件】
  ① src/components/widget/widgets/XxxWidget.vue   新建组件
  ② src/components/widget/WidgetBox.vue           在 WIDGETS 表登记 type → 组件
  ③ src/stores/desktop.js 的 defaultLayout()      想默认就摆一个，加一条 widget
  ④ 组件里要"能拖 / 能改内容" → 用 useDragGrid + desktop.setWidgetProps

【5.3 新增一个 Pinia store】
  位置：src/stores/xxx.js，写法照 worldbook.js / memory.js：
  defineStore('xxx', () => { ... return { state, getter, action } })
  约定：storage key 用 'vphone.xxx.v1'；读档时用 normalize 补默认值，别直接信任老数据

【5.4 新增 AI 提示词】
  · 只服务微信语气 → src/api/chatPrompt.js（buildAlivePrompt / FINAL_OUTPUT_RULES）
  · 服务记忆总结   → src/api/memory.js（buildMemorySystemPrompt）
  · 新 App 要自己的提示词 → 在 src/api/ 下新建 XxxPrompt.js，别塞进别的文件
  约定：提示词写成导出的函数或常量，业务层只拼 messages，不把长文案写进 .vue

【5.5 新增本地存储 key】
  先想清楚是"结构化数据"还是"图片"：
  · 结构化 → localStorage，key 命名 vphone.<模块>.v<版本>，统一走 utils/storage.js
  · 图片   → IndexedDB（putImage / getImageURL），只在 localStorage 里存 key
  需要"老数据自动升级"时，参考 aiConfig.js / worldbook.js / Wechat.vue 的迁移写法：
  读旧 key → normalize → 写新 key → 不删旧数据（除非确认无害）

【5.6 新增一个弹层 / 抽屉】
  放 src/components/<模块>/ 下，命名 XxxPanel.vue / XxxSheet.vue；
  项目没有全局 Toast 组件，各页自己用一个 toast ref + 定时清空（现有写法即如此）

第 6 节 · 命令 & 验证
====================================================================

  npm run dev       启动开发服务器（http://localhost:5173，手机同 WiFi 可用 IP 访问）
                    ⚠ 会一直占着终端，属于"开着看效果"用
  npm run build     打包一次。★ 这是本项目唯一的验证方式：不报错就算改对了
  npm run preview   本地预览打包结果（http://localhost:4173）
  npm run icons     重新生成三个 PWA 图标（改完 scripts/gen-icons.mjs 才需要跑）

  验证顺序（每次改完照做）：
  ① npm run build    看有没有红字报错
  ② 看报错文件名和行号，只回去改那一处（不要"顺手重构"）
  ③ 需要看效果再 npm run dev

  常见报错对号入座：
  · "Failed to resolve import '@/xxx'"   → 路径写错或文件没建（@ = src）
  · "Cannot read properties of undefined" → 多办了老存档没补字段，检查 normalize 函数
  · 图标在开发时正常、打包后空白          → uno.config.js safelist 漏了类名
  · 改了数据但页面没变                    → store 没落盘，或页面读的是本地副本（如记忆 App 的 readChats 快照）
