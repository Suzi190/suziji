**世界书**（`src/stores/worldbook.js`，条目 `vphone.worldbook.v2` + 文件夹 `vphone.worldbook.folders.v1`；完整界面在 `src/views/apps/WorldBook.vue`）
```js
字段（对齐 SillyTavern World Info）：
  { id, title, scope:'global'|'local', folderId, keys:[], requireAll, content,
    position:'before'|'middle'|'after', depth:1~10, constant, order, enabled }
  scope=global 所有对话自动参与；scope=local 只在勾选了它的会话参与
  position      before=人设之前，middle=人设之后，after=插进最近几条聊天（depth 生效）
  constant      必读：不看关键词，每轮都注入
  folderId      所属文件夹 id（'' = 未分组），只影响列表分组，不参与注入
文件夹字段    { id:'wf_…', name, scope:'global'|'local', order, collapsed }
导出常量      WB_POSITIONS / WB_SCOPES / WB_DEPTH_MIN/MAX / WB_ORDER_MIN/MAX / WB_FOLDER_NAME_MAX
state        entries            // 首次带 4 条示例（各演一种用法）
             folders            // 默认空；全局 / 局部各自一套
getters      total, enabledEntries, globalCount, localCount, requiredCount, disabledCount
actions      add(), update(id, patch), remove(id), duplicate(id), toggle(id),
             addFolder({name,scope}), renameFolder(id,name), toggleFolder(id), removeFolder(id),
             collect({ ids, scanText })  // → { before:[], middle:[], after:[{content,depth}], picked:[] }
```
- 注入流程：`collect()` 先筛（启用 + 范围 + 正文非空）→ 命中判定（必读直接过 / 否则关键词命中）→ 按 `order` 排序 → 分红 `before / middle / after` 三组
- 文件夹只是「列表怎么分组」：`removeFolder()` 不删条目，里面的条目 `folderId` 松开回到「未分组」；条目换范围时 `update()` 自动清掉跨范围的 `folderId`
- 微信没用 `collect()` 之外的东西，新 App（文游、论坛）想接世界书，照 `Wechat.vue` 的 `buildMessages()` 抄摆位即可

**记忆**（`src/api/memory.js` 提示词 + `src/stores/memory.js` 仓库，`vphone.memory.v1`；界面在 `src/views/apps/Memory.vue`）
```js
条目字段      { id, text, level:3|2|1, kind, when, quote, hits, at }
              3 = ★★★ 关键 / 2 = ★★ 重要 / 1 = ★ 次要（level 越高注入越靠前、越优先）
导出常量      MEMORY_LEVELS / MEMORY_KINDS / MEMORY_MAX_ITEMS / MEMORY_INJECT_MAX / MEMORY_STORAGE_KEY
api          buildMemorySystemPrompt(char, user, extra)  // 总结提示词（含轻重缓急判定规则）
             buildMemoryPayload({ session, items, fromIndex, userName, extraPrompt })
             parseMemoryReply(text)   // JSON / ```json / 「★★★ 句子」兜底都能吃
             summarizeChat({ config, session, items, fromIndex, userName, extraPrompt, signal })
store        books:{ [chatId]: { chatId, name, items, coveredCount, lastAt } }
             absorb(chatId, { name, items, coveredCount })  // → { added, merged }
             collect(chatId, { max, minLevel })  // 按等级取前 N 条
             render(chatId, options)             // 拼成一段 system；没记忆返回 ''
             pendingRounds(chatId, messages)     // 还有几条「我」的消息没整理
             addItem / updateItem / cycleLevel / removeItem / clearBook / resetProgress
```
- `coveredCount` = **原始 messages 数组下标**（不是过滤后的条数），微信 `autoSummarize()` 与记忆 App 都按这个口径算进度
- 提示词原则：**不按关键词触发**（不能「出现『别』就记」），先教模型用三个问题筛（过一阵还成立吗 / 下次会不会做错 / 这是关系还是这次聊天），并专列「不该记的」，底线只认长期成立的
- 解析兜底：`parseMemoryReply` 里 `capMinor()` 硬性把 `level 1` 限到 2 条，模型不听话时也不会一次吐一堆流水账
- 微信侧：`buildMessages()` 里 `memory.render()` 注入「【你记得的事】」；回完一条且攒够 `rounds` 就静默 `autoSummarize()`（失败只写控制台）
- **携带条数** `memory.injectMax`（0~30，默认 `MEMORY_INJECT_MAX`=12）：每次聊天注入几条，`0` = 只整理不注入（合法值，读取一律用 `??` 兜默认，不能用 `||`）；在微信「⋯ → 聊天记忆 → 携带条数」改，记忆 App 里只读显示
- 和世界书**解耦**：世界书按关键词/位置注入，记忆按等级注入，两边都只在 `buildMessages()` 里各占一段

- 活人感（`src/api/chatPrompt.js` 的 `buildAlivePrompt(name)`）：一段独立 system，管「怎么把话说出来」——回得短、会敷衍、不接客服话术、只发说出口的字、不用 markdown / 旁白；人设 `persona` 仍然管「这个人是谁」。改语气先改 persona，嫌 AI 味重再调这段；单个好友可在「⋯ → 活人感」关掉对比
- 气泡格式（`chatPrompt.js` 的 `FINAL_OUTPUT_RULES` + `src/utils/bubbles.js`）：每轮最后一条 system 要求 `[s]…[/s]` 包住每个气泡（和人设、活人感都解耦，关不掉）；`sendText()` 流式时用 `stripBubbleTags()` 先剥标签显示，收完用 `splitBubbles()` 拆成多条消息（同一时间戳，不插时间条），AI 历史也会补回标签发回去。要换气泡格式只改这两处，别在 `ChatRoom.vue` 里再写一份解析
- 常见需求改哪里：换 AI 语气 = 改某个好友的 `persona` 文案；加好友 / 改头像色 = 在微信「通讯录」里点；气泡颜色 = 「我 → 聊天气泡」；表情 = 「我 → 表情包」；
  聊天背景 / 拉黑 / 世界书勾选 / 查找记录 = 聊天页右上角「⋯」（世界书只列「局部」条目，「全局」的自动生效；改条目内容去「世界书」App）
- 已留接缝：`buildMessages()` 里有一行 TODO，记忆模块接上后把 `item.memory.summary` push 成 system 消息就行（表单已经能存）
- 记忆现状：**只存设置，不调 AI**（传统总结的轮数 / 自定义提示词都会被记住，等记忆模块统一接线）

## 4. 我判断"不用动"的标准（你可以直接用这些话拒绝我）

- 你需求里**没提到**的 App → 一律不动
- 🔴 地基层 → 默认不动；真要动，改动卡里单独列「副作用 + 是否影响已存数据」
- 已有积木 → 只调用，**不复制第二份**
- 不在本次需求里的"顺手优化" → 不做，最多写在末尾提示你
- UI 风格约定（磨砂玻璃、无阴影、低饱和、432×958 设计像素）→ 不擅自改

## 5. 你说话越随意越好，这三种说法都行

1. 「我想让 ___ 变成 ___，其他别动」
2. 「我只要它能跑，样式先别管」
3. 「这块我不确定，你**先给方案别改代码**」

连效果都说不清也行 —— 说「我觉得微信太丑了 / 太卡了 / 不知道点哪」，我会先问 1~2 个具体问题，然后给方案。

## 6. 万一改坏了怎么回退

- 数据全在 localStorage，key 都是 `vphone.*`；设置页有「清除本地缓存」和导入/导出
- 布局结构改过会动 `desktop.js` 里的 `LAYOUT_VERSION` 走迁移；**改动涉及已存数据时，我会在改动卡里明确写「需要清缓存」**
- 项目目前没有 git，重要节点建议先手动复制一份整个文件夹做快照
